# wiki-reads — 위키 기반 읽을거리 큐레이션

위키의 관심사·진행 상태·막힌 문제를 정밀 분석하여, 정확히 지금 필요한 읽을거리를 웹에서 찾아 큐레이션한다.

> **출력 언어 = 한국어 (불변식).** 이 본문이 영어로 쓰여 있든 한국어로 쓰여 있든, 사용자에게 보이는 모든 산출물(큐레이션 목록·요약·번역)은 한국어로 낸다. 기술 용어(GRPO, advantage 등)만 영어 유지.

## 출력 모델

**위키 전체 폭을 대표한다.** 한 실행은 능동 프로젝트 축(LLM·투자 등)과 정적 지식 축(미술·미식·멘탈모델·러닝 등)을 **함께** 다룬다. 특정 도메인으로 좁히는 건 인자(`/wiki-reads 미술`)로만 한다.

**축(axis)당 슬롯 2개 — ① Recency 슬롯(Fresh 또는 Recent) + ② Classic.**

Fresh와 Recent는 **하나의 Recency 슬롯**이다. 그 축에서 고른 항목의 발행일이 7일 이내면 `Fresh`, 아니면 `Recent`로 라벨만 다르게 붙인다. 둘을 동시에 내지 않는다 — 그래서 축당 최대 2개(Recency 1 + Classic 1).

**폭 vs 분량 — 로테이션으로 균형:**
- 축이 ~5개 이하면 전 축을 매 실행 다룬다(축당 최대 2개 → 총 ~10개).
- 축이 그보다 많으면 한 실행에 다 싣지 말고 **로테이션**한다: ⓐ log.md의 직전 `WIKI_READS` 항목을 보고 **지난 주기에 안 다룬 축을 우선**, ⓑ 이번에 깊게 다루는 축은 2슬롯, 나머지 축은 **"이번 주기 신규 없음 / 다음 주기"** 한 줄로 명시해 **빠진 도메인이 보이게** 한다(조용히 누락 금지). 즉 분량은 ~10개로 묶되, 사용자는 위키 전체가 시야에 있음을 매번 확인할 수 있다.
- 깊게 다룰 축 선정: 신규 가능성(능동 개발·최근 update 잦음) × 마지막으로 다룬 지 오래된 정도.

| 티어 | 범위 | 역할 |
|---|---|---|
| **Fresh** | 발행일 **오늘부터 역산 7일 이내** | Recency 슬롯이 7일 이내일 때의 라벨 |
| **Recent** | 발행일 **오늘부터 역산 6개월 이내** (전 축 통일) | **주력.** 연구 프런티어 — "지금 확장 가치" 최우선 |
| **Classic** | foundational 원전·책·고전 에세이 (연도 무관) | 축의 기초를 메우는 원전 |

- **Recency 슬롯이 주력이다.** 각 축에 6개월 이내 항목 1개를 목표로 하고, 7일 이내면 Fresh로 라벨링. 6개월 이내 적격 항목이 0개면 그때만 슬롯을 비운다 (범위를 1년으로 늘리지 말 것).
- **Classic은 미인제스트 원전만.** 이미 위키(`concepts/` · `entities/` · `references/`)에 인제스트된 것은 후보에서 자동 제외. 재독·재제안 금지.
- 개수 채우기보다 "지금 이 위키를 확장할 가치"가 최우선. 품질 미달이면 슬롯은 비운다.

## Before You Start

1. Read `.env` to get `OBSIDIAN_VAULT_PATH`
2. Read `$OBSIDIAN_VAULT_PATH/index.md` to understand the wiki's scope and structure
3. Read `$OBSIDIAN_VAULT_PATH/log.md` for recent activity context

## 실행 — Phase 1~4 자동, Phase 5~6 사용자 선택

### Phase 1: 위키 프로파일 추출

Explore 에이전트로 위키를 정밀 스캔한다. **목표: 축별 검색 쿼리를 만들기 위한 키워드 추출 + Classic 후보 배제 목록 확보.**

**목표는 위키 전체 폭을 대표하는 것이다.** 능동 개발 중인 프로젝트 축만이 아니라, 정적 지식 도메인(미술·미식·멘탈모델·러닝 등 "막힌 문제"는 없지만 사용자가 계속 키우는 관심사)도 똑같이 후보로 본다.

핵심 페이지 스캔 (frontmatter tags/summary + 본문 핵심):
- index.md의 **모든 최상위 섹션** (Projects / Concepts / Entities / Synthesis / References) — 여기에 위키의 관심 클러스터가 다 드러난다
- 진행 중인 프로젝트 페이지 (updated 최근 우선) + "로드맵·다음 단계" 미래 지향 페이지
- concept·synthesis 허브 페이지 (학습-플로우, 격자틀, 한국-현대미술-지형도, 서울-레스토랑 등 — 도메인 막론)

추출할 것:
- **관심 축**: 위키의 **모든 주요 관심 클러스터**를 열거한다 (예시에 끌려가지 말 것 — 축은 *이번* 볼트의 index.md 섹션·태그 분포에서 도출). 개수를 3~5로 미리 자르지 말고, 일단 전부 뽑은 뒤 Phase 4에서 로테이션으로 분배한다.
- **축별 현재 상태**: 능동 축이면 "막힌 문제 / 다음 마일스톤", 정적 축이면 "최근 갱신·확장 중인 갈래 / 비어 있는 하위 영역" — 둘 중 해당하는 쪽으로
- **축별 추적 중인 엔티티·고유명사**: 모델명·기업명·기술명·작가명·평론가·식당 카테고리 등 (도메인 무관)
- **기존 인제스트 목록** (Classic 중복 배제용): `concepts/` · `entities/` · `references/` 페이지 제목 + frontmatter `sources:` 수집

Phase 1에서 위키 전체 본문을 읽지 말 것. index.md(전 섹션) + log.md + 핵심 페이지 frontmatter 수준으로 충분하다.

### Phase 2: 축별 쿼리 생성 (Recent 주력 + Classic + Fresh)

**이번 실행에서 깊게 다루기로 한 축**(출력 모델의 로테이션 규칙으로 선정)에 대해서만 **쿼리 2개**(Recent 1 + Classic 1)를 만든다. 로테이션으로 미루는 축엔 쿼리를 돌리지 않는다(분량·검색비 절약). Recent 쿼리 하나로 Fresh(7일 이내)까지 자연히 걸리므로 별도 Fresh 쿼리는 만들지 않는다 — Phase 3에서 Recent 결과의 발행일을 보고 7일 이내면 Fresh로 승격한다.

**Recent 쿼리** (축당 1개, 주력):
- 축의 "가장 핫한 막힌 문제 또는 다음 마일스톤"을 직격하는 영문 키워드
- 발행일 제한: 직전 6개월 (예: `after:YYYY-MM-DD` 오늘-6개월, 또는 최신 연·월 키워드)
- arxiv·공식 블로그·학회·신뢰 뉴스레터 쪽으로 유도하는 site 힌트 포함
- 쿼리에 **검색 의도 한 줄** 첨부 ("왜 이걸 찾는지")

**Classic 쿼리** (축당 1개):
- 축의 foundational 문헌을 겨냥 — 교과서 챕터, seminal paper, 고전 에세이, 업계 레전드의 에세이
- 연도 제한 없음. 배제 목록(Phase 1에서 수집한 기존 인제스트)에 걸리는 저자·제목은 쿼리에서 피함
- 쿼리에 **검색 의도 한 줄** 첨부

쿼리 품질 기준:
- 구체적 키워드 (알고리즘명, 모델명, 벤치마크명, 저자명)
- Recent는 연·월 제약 권장, Classic은 "seminal", "original", "foundational", "classic essay" 같은 시그널어
- 검증 가능한 소스가 나올 만한 쿼리
- **arxiv ID = 발행 연·월**이라는 점을 활용(예: `2602.xxxxx` = 2026년 2월). `after:` 연산자는 엄격히 걸러지지 않으므로 결과의 실제 발행일을 ID·페이지로 직접 검증할 것.

### Phase 3: 웹 서치 + 필터링

WebSearch로 쿼리 일괄 실행. 결과마다 다음 기준으로 필터.

**우선 소스**:
- arxiv.org (논문)
- 공식 블로그 (NVIDIA, HuggingFace, Google, Meta, ByteDance 등)
- 학회 proceeding (ACL, ICML, NeurIPS, COLM 등)
- 신뢰 미디어 (Bloomberg, Power Magazine 등 전문지)
- 검증된 뉴스레터 (Sebastian Raschka, Interconnects 등)

**Recent 필터 — 주력**:
- 발행일이 **오늘 - 6개월 이내**가 아니면 탈락. 명확한 발행일을 확인할 수 없으면 탈락
- 6개월 이내 항목 중 **발행일이 오늘 - 7일 이내인 것은 Fresh로 승격** 표시
- 6개월 이내 항목이 0개면 그때만 Recent 슬롯을 비운다 (범위를 1년으로 늘리지 말 것)

**Fresh 승격 — 보너스**:
- Recent 결과 중 7일 이내인 항목만 Fresh로 라벨. 별도 검색 불필요
- 없으면 Fresh 헤더 자체를 출력하지 않는다 (빈 슬롯 표기 금지)

**Classic 필터 — 중복 배제**:
- Phase 1에서 수집한 기존 인제스트 목록(제목·sources URL)에 걸리면 탈락
- 같은 저자·같은 주제의 다른 원전을 대신 고려 가능 (단, 그것도 배제 목록에 없어야 함)

**공통 제외**:
- Medium 일반 블로그 (저자가 유명하지 않은 경우)
- SEO 스팸성 "Top 10" 리스트
- 날짜 없는 글
- 내용 없는 뉴스 재탕
- "YYYY Outlook" / "Year in Review" 류 시한 만료된 전망 기사
- 이후 논문/이벤트에 의해 명백히 superseded된 1~2년 전 survey·리포트

### Phase 4: 큐레이션 + 제시

축별로 **Recent 1 + Classic 1**을 고르고, Recent 중 7일 이내가 있으면 그 자리에 **Fresh** 라벨을 얹는다. **모든 티어가 채워지지 않아도 된다 — 억지로 채우지 말 것.**

선택 원칙:
1. **위키 확장 가치 최우선**: 읽고 나서 기존 페이지를 업데이트·분기시킬 여지가 큰가?
2. **현재 막힌 문제 해결 기여도**: Phase 1에서 뽑은 블로커를 건드리는가?
3. 동률이면 사용자 관심 이동 방향(최근 update 잦은 영역)에 가까운 쪽

출력 형식 (축별 블록):
```
═══ [축 이름] ═══

Fresh [YYYY.MM.DD]          ← 7일 이내일 때만 이 헤더 출력, 없으면 통째로 생략
N. 제목 (한국어 번역)
→ URL
위키 연결: [[관련-페이지]] — 이 항목이 풀어주는 막힌 문제 / 확장 포인트 한 줄

Recent [YYYY.MM]
N. 제목 (한국어 번역)
→ URL
위키 연결: [[관련-페이지]] — 이 항목이 풀어주는 막힌 문제 / 확장 포인트 한 줄

Classic [YYYY]
N. 제목 (한국어 번역)
→ URL
위키 연결: [[관련-페이지]] — 이 원전이 축의 어떤 기초를 메우는지 한 줄
```

- **Fresh는 7일 이내일 때만** 헤더를 낸다. 없으면 헤더 자체를 출력하지 않는다 (`없음` 표기 금지).
- Recent/Classic이 비면 그 헤더 아래 `— 6개월 이내 적격 항목 없음` / `— 배제 목록 외 Classic 후보 없음`으로 명시 (숨기지 말 것).
- 최종 한 줄 요약: "이번 주 우선 추천: N번 → N번 (이유)" — 전체에서 1~2개만
- 응답 채널이 텔레그램이면 4096자 단위로 축별 분할 전송. 터미널이면 분할 없이 한 번에.
- **로테이션 메모리**: 제시 후 `log.md`에 한 줄 남긴다 — `[YYYY-MM-DD] WIKI_READS axes_deep="다룬 축" axes_deferred="미룬 축" items=N`. 다음 실행이 이걸 읽어 미룬 축을 우선한다. (인제스트와 무관한 가벼운 마커 — 본문 변경 아님)

**형식 예시 — Fresh 없는 축 + Fresh 있는 축 (주제는 무관, 형식만 보라):**
```
═══ 투자 ═══                                ← 비-AI 도메인. 소스도 arxiv가 아니라 memo·에세이

Fresh [2026.05.28]                          ← 7일 이내라 Recent 대신 Fresh로 라벨
8. (제목)
→ URL
위키 연결: [[하워드-막스-메모-아카이브]] — (한 줄)

Classic [연도]
9. (제목)
→ URL
위키 연결: [[투자자]] — (한 줄)

═══ Continual Learning / CPT ═══            ← Fresh 헤더 없음 = 7일 이내 항목이 없다는 뜻

Recent [2026.01]
3. (제목)
→ URL
위키 연결: [[cpt-forgetting-방지-전략]] — (한 줄)

Classic [연도]
4. (제목)
→ URL
위키 연결: [[cpt-forgetting-방지-전략]] — (한 줄)
```
- Fresh와 Recent는 **같은 슬롯**이다 — 7일 이내면 Fresh, 아니면 Recent. 한 축에 둘 다 내지 않는다.
- **위 축·주제·소스 유형은 형식 설명용 더미다.** 실제 축은 Phase 1에서 *이번* 볼트로부터 매번 새로 도출하고, 소스 유형은 도메인에 맞춰 고른다(기술 축=arxiv·공식 블로그, 투자 축=memo·셀사이드·서적, 미술/미식 축=비평·가이드 등). 예시가 LLM·투자라고 해서 그 두 축으로 좁히지 말 것.

### Phase 5: 읽기 + 번역 (사용자 선택)

사용자가 "N번 읽자", "순서대로 읽자" 등으로 요청하면 실행.

각 항목에 대해:
1. WebFetch로 원문 전체 추출 (HTML 버전 우선, PDF는 abstract 페이지 경유)
2. 한국어로 번역하며 요약:
   - 한 줄 요약
   - 핵심 방법/발견 (수식, 테이블 포함)
   - 실험 결과
   - **위키 프로젝트 적용 포인트** (가장 중요 — "이걸 어디에 쓸 수 있는지")
3. 사용자에게 전달 (응답 채널이 텔레그램이면 4096자 단위 분할, 터미널이면 그대로)

규칙:
- 기술 용어는 영어 유지 (GRPO, advantage, gradient 등)
- 수식은 텍스트로 표현
- 논문이면 섹션별 구조 유지, 블로그면 핵심만
- 사용자 질문에 쉬운 비유로 답변

### Phase 6: 위키 인제스트 (사용자 선택)

사용자가 "인제스트해", "위키에 넣어" 등으로 요청하면 실행.

각 읽은 항목에 대해:
1. `$OBSIDIAN_VAULT_PATH/concepts/` 아래에 위키 페이지 생성
   - frontmatter: title, category, tags, summary, sources, created, updated, provenance
   - 본문: 핵심 내용 + 실험 결과 + 적용 가능성
   - 관련 페이지: 기존 위키 페이지와 cross-link
2. 관련 기존 페이지에 역방향 링크 추가 (허브 페이지, 전략 페이지 등)
3. `index.md` Concepts 섹션에 추가
4. 커밋은 별도 요청 시에만

## 주의사항

- Fresh(7일)·Recent(6개월) 기준은 **오늘 날짜 기준**으로 계산. 오늘 날짜는 세션 컨텍스트의 `currentDate`(또는 `date +%F`)로 확인하고, 거기서 7일·6개월을 역산할 것. 학습 컷오프나 기억으로 추정하지 말 것.
- 6개월·7일 창은 **전 축 통일**. 축마다 다른 창을 쓰지 말 것.
- 쿼리 재검색은 Recent 슬롯이 빈 경우가 아니라 **쿼리 자체가 부실한 경우**에만 허용 (최대 1회 리파인).
- 텔레그램 채널로 응답 시 메시지 길이 제한 고려 (4096자 이하로 분할).
